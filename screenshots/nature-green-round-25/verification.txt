What was wrong
--------------
1) Snap mode never re-evaluated after load. snapEnabled was computed once at setup.
   - 1024 -> 767 px (resize or rotation): snap stayed ON below its 961px threshold.
     The page kept .hp-chapters--snap, so the inner scroller AND the document both
     scrolled: measured winY=732 with #hp-ch2 at top=-730, indicator still 02/02.
   - 360 -> 1280 px: snap stayed OFF on desktop, so the desktop two-column grid
     rendered without snap. Sections became content-height and #hp-ch2 landed at
     top=0.4, i.e. 71.6px behind the 72px header.
2) Tablet band 768..960 px. canSnap() is min-width:961px, so tablets use the
   desktop grid with no snap and had no top padding for the fixed header. After a
   rail click the chapter 02 cover sat at y=28.8 with the header at y=0..61
   (32.2px hidden); on load, chapter 01's eyebrow was at y=8.6 and its h1 at
   y=42.4, both behind the header.
3) Reduced motion on desktop. goToChapter() scrolled the window with a manual
   window.scrollTo(el.top + scrollY), which ignores scroll-margin. At 1024x768 the
   chapter 02 cover cleared the 61px header by -2.2px (i.e. 2.2px behind it).
   The global [id] { scroll-margin-top: 92px } (src/styles/_global.scss:65) only
   helps native scrollIntoView / anchors, not the manual scroll.

The fix (frontend/src/views/HomePage.vue only)
----------------------------------------------
1) applySnapPreference() re-evaluates canSnap() on every relevant media change and
   watchSnapPreference() attaches change listeners to (min-width: 961px) and
   (prefers-reduced-motion: reduce). On a mode change it clears layoutReady, waits
   nextTick + one animation frame, restores layoutReady and re-aligns the kept
   chapter with goToChapter(keep, true). Listeners are removed in onBeforeUnmount.
2) goToChapter(idx, instant = false): behavior = instant || reduce ? 'auto' : 'smooth'.
   The window branch now uses el.scrollIntoView({ block: 'start', behavior }) so the
   real scroll-margin applies instead of a manual offset.
3) CSS: .hp-chapters .hp-chapter { scroll-margin-top: 0 } overrides the global 92px
   inside the chapter deck, and at min-width:768px the non-snap deck gets
   scroll-margin-top: var(--bx-chrome-top, 72px) (72 / 61 / 57px by header height).

Resize limitation (documented, not changed)
-------------------------------------------
Within the same mode the scroll offset is preserved, so changing the viewport
height/width drifts the snapped chapter by the delta until the next scroll.
1024 -> 767 is fine (clearance 52.8px); 767 -> 360 leaves the cover 27.6px above
the viewport (header not overlapped, but the top of the book is cut) until the
next scroll re-aligns. No re-align was added inside a mode: it would fight user
scrolling and mobile URL-bar height changes. Cross-mode changes are handled.
