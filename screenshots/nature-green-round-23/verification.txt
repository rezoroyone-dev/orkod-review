Generated 2026-10-22T11:04:12.916Z

Root cause of the boot-time 02/02: snap mode was enabled in onMounted, so the
initial measurement ran before Vue had applied .hp-chapters--snap. In that
transient layout chapter 01 was 326px tall and chapter 02 462.5px in a 788.5px
strip, so chapter 02 won the visible-area test and the rail latched onto it;
no later scroll or resize event re-ran the measurement, so the wrong reading
persisted. The active section is now read positionally (the section whose top is
closest to the top of the visible strip) instead of by pixel area, so a taller
section can no longer win mid-load, and the reduced-motion layout (sections
sized by content, both partly on screen) also starts at 01 / 02. Fix: snap mode is decided during setup (first render already has the
final layout), the first measurement runs after nextTick + one animation frame,
and a ResizeObserver / document.fonts.ready / window load re-sync when late
layout changes happen.

Mobile spacing: chapter 02 on phones is taller than the viewport, so at the
snap point the CTA sat 6px from the bottom edge at 390x844. The section now
uses less air above the cover and slightly more below the button; short
viewports (<=830px tall) trim the cover's own padding too. Button size is
unchanged (173x52) and nothing is hidden.
